# 네트워크설계및구조 인터랙티브 학습 사이트 — 초기 설계

> 목표: 정적인 강의자료(Week 2–7, PDF 6개)를 "한 단계씩 넘기며 보는 애니메이션 + 직접 조작"으로 바꿔서, 시험 범위 개념을 직관적으로 이해하고 오래 기억한다.
> 참고: https://designed-to-scale.vercel.app (레슨/단계 단위 애니메이션 다이어그램)

---

## 1. 정보 구조 (3단 계층)

| 계층 | 이름 | 예시 | 표시 위치 |
|---|---|---|---|
| 대단계 | **Week** | W3 · TCP, UDP & Socket | 왼쪽 사이드바 (아코디언 헤더) |
| 소단계 | **Step** | 3-4 · 3-Way Handshake | 왼쪽 사이드바 (Week 아래 목록) |
| 진행 순서 | **Phase** | SYN → SYN+ACK → ACK → 데이터 | 중앙 하단 진행 바 |

- Week = 강의자료 PDF 1개. Step = 강의자료 안의 내용 묶음(슬라이드 1~6장). Phase = 그 Step의 애니메이션/UI가 진행되는 한 컷.
- 전체 Step 목록과 슬라이드 매핑은 `docs/CURRICULUM.md` 참고.

### URL
```
/#/w3                     → Week 개요 (Step 목록 + 학습 목표)
/#/w3/handshake           → Step 첫 Phase
/#/w3/handshake/3         → Step의 3번째 Phase
```
새로고침해도, 링크를 공유해도 같은 화면이 나와야 한다.

### 2-1. 왼쪽 사이드바 (Step 목록)
- Week 아코디언. 현재 Week는 펼쳐 둔다.
- Step 항목: 번호 + 짧은 제목 + ★(시험 우선). 현재 Step만 배경색으로 강조한다.
- 맨 아래: "Quick Check 모아보기", "오답 노트".
- **진도율·완료 체크는 넣지 않는다.** 이 사이트는 진도를 채우며 공부하는 도구가 아니라, 필요할 때 어려운 개념을 찾아 들어가 애니메이션·인터랙티브 UI로 이해하는 도구다. (Week 개요에도 진도 표시 없음)
- 접기 버튼(아이콘만 남김) → 중앙 무대를 넓게.

### 2-2. 중앙 무대 (Stage)
- 장면 유형(아래 4절) 중 하나를 렌더링한다. SVG 기반, 가로세로 비율 고정(16:10), 반응형으로 확대/축소.
- **두 가지 모드**
  - **따라가기**: 미리 짜인 Phase를 순서대로 재생. 하단 진행 바와 연동.
  - **직접 해보기**: 사용자가 값을 바꾸거나 패킷을 클릭해 손실시키는 등 자유롭게 조작. 이때 하단 바는 Phase 대신 **이벤트 로그**(예: `SYN 손실 → RTO 1s 대기 → 재전송`)를 보여 준다.
  - 직접 해보기가 의미 없는 Step(순수 개념)은 토글을 숨긴다.

### 2-3. 하단 진행 바 (Phase 표시, 높이 ~72px)
- Phase 점(●○)과 짧은 라벨(8자 이내), `현재 / 전체` 표시.
- 컨트롤: ◀ 이전, ⏯ 자동재생, ▶ 다음, 속도(0.5x/1x/2x), ↺ 처음부터.
- 마지막 Phase에서 ▶ → "다음 Step으로" 버튼으로 바뀐다.
- 키보드: `←/→` Phase, `[` / `]` Step, `Space` 재생/정지.

### 2-4. 오른쪽 상세 설명 패널
- 현재 **Phase에 연동**해서 내용이 바뀐다.
- 구성
  1. Phase 제목
  2. 본문 (2~5문장, 강의자료 기반)
  3. 핵심 포인트 박스 (강의의 "핵심:" 문장)
  4. ⚠ 흔한 오해 / 실무 신호 (강의의 "오해 vs 실제", "실무 신호" 문장)
  5. 📄 출처 칩: `W3 p.10–11` (클릭하면 해당 페이지 이미지 미리보기, 선택 사항)
- 탭: **설명** | **쉽게 보기** (강의의 "쉽게 보기" 비유 슬라이드가 있는 Step만) | **퀴즈** (Step 마지막에 체크 질문)
- 1024px 미만에서는 오른쪽 패널을 드로어로 바꾼다. (데스크톱 학습이 기본이고, 모바일은 보기만 가능하면 충분)

## 3. 데이터 모델 — 콘텐츠와 렌더러를 분리한다

핵심 원칙: **Phase = 화면 상태 스냅샷**, **애니메이션 = 두 스냅샷 사이의 전환**.
레슨을 추가할 때 컴포넌트 코드를 새로 짜지 않고 데이터만 쓰는 구조를 목표로 한다.

```ts
// src/content/types.ts
export type Week = {
  id: 'w2' | 'w3' | 'w4' | 'w5' | 'w6' | 'w7';
  no: number;
  title: string;           // "TCP, UDP & Socket"
  question: string;        // 강의의 "오늘의 질문"
  objectives: string[];    // Learning Objectives
  source: string;          // PDF 파일명
  steps: Step[];
};

export type Step = {
  id: string;              // "handshake"
  no: string;              // "3-4"
  title: string;
  slides: number[];        // 강의자료 페이지 [10, 11]
  scene: SceneType;        // 아래 4절
  sandbox?: boolean;       // 직접 해보기 지원 여부
  easy?: Explain;          // 쉽게 보기 (비유)
  phases: Phase[];
  quiz?: Quiz[];
};

export type Phase = {
  label: string;           // 하단 바 라벨: "SYN+ACK"
  title: string;           // 오른쪽 패널 제목
  body: string;            // 오른쪽 패널 본문 (**굵게**, "· " 목록, ① 목록만 해석)
  keyPoint?: string;
  pitfall?: string;        // 흔한 오해
  signal?: string;         // 실무 신호
  scene?: SceneType;       // 이 Phase만 다른 장면으로 그릴 때 (예: 3-4의 연결 비용 → chart)
  state: unknown;          // 장면 유형별 상태 (SequenceState, TopologyState ...)
};

export type Quiz = {
  q: string;
  choices?: string[];      // 없으면 주관식(본인 말로 쓰고 → 모범답안 공개)
  answer: string;
  why: string;
};
```

**오른쪽 패널 글쓰기**
- 대학생이 처음 읽어도 이해할 수 있게 쓴다. 강의자료 문장을 그대로 옮기지 않는다.
- 핵심은 그 기술의 **배경과 흐름**이다. "왜 필요한가 → 무엇을 주고받는가 → 그래서 무엇이 가능해지는가"가 Phase를 따라 이어지게 쓴다.
- 한 화면(스크롤 없이)에 들어오게 핵심만 짧게. 첫 문장은 앞 단계와 잇고 마지막 문장은 다음 단계로 넘겨 **내용 흐름**이 이어지게 한다.
- 읽기 쉽게: 제목 17px, 본문 12.8px·줄간격 1.65. 보조 상자 모양은 아래 "디자인 언어"의 가이드 규칙을 따른다. "주고받은 메시지"는 지난 메시지를 한 줄로, 이번 단계 메시지만 뜻풀이까지. 본문 표기는 `**굵게**`(핵심 용어), `· ` 글머리 목록, `①` 번호 목록만 쓴다 (`components/layout/RichText.tsx`).
- 이해에 필요하면 부연 설명과 비유("쉽게 보기")를 넣는다. 강의자료에 없는 내용은 코드에 `// 보충` 주석으로 표시하고, 사실관계는 강의자료와 어긋나지 않게 한다.

## 4. 장면 유형 (재사용 컴포넌트 = "엔진")

강의자료 6개를 분석해 보면 시각 자료가 거의 다음 유형으로 수렴한다. 이것들을 먼저 탄탄하게 만들어 두면 나머지는 데이터 작업이다.

| 유형 | 설명 | 주 사용처 |
|---|---|---|
| `sequence` | **시퀀스(래더) 다이어그램**. 세로 생명선 2~4개, 메시지 화살표가 순서대로 날아감, 양옆에 상태 라벨(SYN_SENT 등), 메시지 클릭 시 손실 처리 | 3-way/4-way, DHCP, DNS 질의, TLS, CORS Preflight, 로그인, OAuth, WebSocket, MQTT QoS |
| `topology` | **네트워크 토폴로지**. 노드(PC·스위치·라우터·서버·브로커)·링크·이동하는 패킷. 패킷에 헤더 라벨, 노드에 표(NAT/ARP/라우팅 테이블) 부착 | 라우팅, Hop별 MAC/IP, NAT, ARP, Mux/Demux, MQTT, WebRTC |
| `bits` | **비트/주소 계산기**. 10진↔2진, prefix 슬라이더, AND 연산 애니메이션, 주소 범위 띠 | Subnet, CIDR, Broadcast, 서브넷 분할 |
| `anatomy` | **해부도**. 구조화된 텍스트/필드에 마우스를 올리면 의미 강조 | URL, HTTP 메시지, TCP/UDP 헤더, JWT, WS Frame, dig 출력, 코드 |
| `flow` | **파이프라인/플로차트/상태도**. 박스와 화살표, 현재 단계 강조 | URL 입력 후 과정, Backend 요청 경로, TCP 상태 전이도, 상태코드 결정 트리 |
| `chart` | **그래프 시뮬레이터**. 파라미터를 바꾸면 그래프가 실시간으로 변화 | cwnd(Slow Start/AIMD), Polling 비용, 메시지당 바이트, 연결 비용 |
| `compare` | **나란히 비교**. 같은 시나리오를 두 방식으로 동시 재생 | TCP vs UDP, HTTP/1.1 vs 2 vs 3, Session vs JWT, Mesh/SFU/MCU |
| `sandbox` | **전용 플레이그라운드**. 입력하면 결과가 바뀌는 맞춤형 UI | bind 주소 시뮬레이터, CORS 요청 빌더, Origin 비교기, Wildcard 매칭, 공격 실습실 |
| `diagnose` | **진단 시뮬레이터**. 증상/오류 메시지를 고르면 의심 계층과 확인 명령을 강조 | 매주 나오는 "증상 → 원인 매핑", "Troubleshooting Ladder" |
| `quiz` | Quick Check 전용 화면 | 매주 마지막 Step |

### 시각 규칙 (모든 Week 공통)
계층·프로토콜마다 색을 고정하면 주차가 바뀌어도 같은 시각 언어로 읽힌다.

| 대상 | 색 | 대상 | 색 |
|---|---|---|---|
| L2 / MAC | 회색 | HTTP | 보라 |
| L3 / IP | 파랑 | TLS / 암호화 | 금색 + 자물쇠 아이콘 |
| TCP | 초록 | DNS | 청록 |
| UDP | 주황 | 손실 / 오류 / 차단 | 빨강 + ✕ |

### 디자인 언어 (사이트 전체)
참고: designed-to-scale.vercel.app의 시각 언어(종이색 바탕, 고정폭 글꼴, 단단한 그림자, 파스텔 블록)를 따르되 구현과 그림은 직접 만든다.

- **바탕과 글자**: 따뜻한 종이색 바탕(`canvas` #f4ebe0), 카드(`surface`), 잉크색 글자(`ink` #1d1b18). zinc 회색은 따뜻한 회색으로 덮어쓴다 (`src/index.css`의 `@theme`).
- **글꼴**: 화면 전체를 고정폭(JetBrains Mono) 하나로. 한글은 Noto Sans KR로 채운다. 기본 13px.
- **공통 부품** (`src/index.css`): `.tool` 버튼(잉크 테두리 + 아래로 1.5px 단단한 그림자, 누르면 내려감, 켜짐은 연두), `.tag` 알약, `.card`(옅은 테두리 + 부드러운 그림자), `.stage-chip`(무대 위 설명: 반투명 종이 + 왼쪽 색 막대).
- **레이아웃**: 왼쪽 사이드바는 바탕 위에 바로(트리 선으로 Step 연결, 펼침은 높이가 부드럽게 늘어남), 가운데(헤더 + 무대 + 진행 타임라인)와 오른쪽 설명은 각각 카드.
- **진행 바 = 타임라인**: 번호 점 + 진행만큼 채워지는 선. 지금 Phase 점은 연두 + 단단한 그림자, 지난 Phase는 옅은 연두.
- **오른쪽 설명 = 가이드**: Phase 표시 → 제목 → 본문 → 보조 상자. Phase가 바뀌면 내용이 위에서부터 차례로 미끄러져 들어온다(`.guide-in`). 보조 상자(`PanelSection`)는 왼쪽 아이콘 칸 + 작은 대문자 제목, 종류는 바탕색으로만 구별(핵심 포인트 연두, 흔한 오해 분홍, 실무 신호 연보라, 주고받은 메시지 종이색).
- **움직임**: 감속 곡선 하나(`cubic-bezier(.2,.7,.2,1)`, `EASE`)와 등장 0.36초(`ENTER`)를 모든 곳에 쓴다. 테두리 빛 같은 강조 효과는 쓰지 않는다.
- **바닥 물결**(`FloorRipple`): 오브젝트에 설명 알약이 뜨는 순간(topology의 알약, sequence의 상태 알약이 바뀔 때) 그 블록 바닥에서 원 하나가 한 번 퍼져 나가 "여기를 보라"고 알린다. 색은 알약 글자색, 1.1초. Phase 시작부터 있던 알약에는 없다. `prefers-reduced-motion`이면 반복·등장 애니메이션을 끈다.

### 무대 (모든 엔진 공통, `src/scenes/iso/`)
- **2:1 아이소메트릭 투영**(`geometry.ts`, 바닥 마름모 가로:세로 = 2:1). 무대 바탕은 종이색 + 연한 격자(`IsoGrid`).
- **이동·확대**(`usePan`): 드래그로 이동, 휠·트랙패드 핀치로 커서 자리를 기준으로 확대·축소(0.5배 ~ 3배). 확대·축소도 끌기와 같은 느낌으로, 굴린 만큼 **즉시·연속으로** 따라온다(애니메이션·관성·단계 없음, 그림 묶음 transform으로 바로 적용). 카메라 이동만 부드럽게 움직인다. 화면에 배율 막대는 두지 않고, 바꿨을 때만 오른쪽 위에 "맞춤"(원래 자리와 크기) 버튼이 나온다. 배율은 Phase를 넘겨도 유지되고 Step이 바뀌면 초기화, 이동은 Phase가 바뀌면 초기화.
- **블록**(`IsoBlock`): 둥근 모서리, 옆면·윗면 파스텔 그라데이션, 윗면 광택, 앞 모서리 흰 하이라이트, 잉크색 외곽선, 바닥에 번진 그림자. 색은 `BLOCK_PALETTE`(blue, violet, green, orange, yellow, slab).
- **기기**(`IsoDevice`): 클라이언트 = 보라 블록 + 모니터 아이콘, 서버 = 파랑 블록 + 서버 아이콘. **이름은 블록 앞면에 직접** 쓴다.
- **글자 상자 = 알약**(`PillBox`, `TAG`): 잉크색 얇은 테두리 + 아래로 단단한 그림자. 색은 `PILL_TONES`(paper, green, orange, amber, red, violet, gray). 상태 이름은 기기 위 알약(평소 종이색, 완료 연두, 대기 호박, 오류 빨강, 모름 회색).
- **연결선**: 검은 선 + 작은 화살촉(`IsoArrow`). 주고받는 연결이면 양방향.
- **패킷**: 잉크 테두리의 작은 원. 클라이언트 → 서버는 연두, 반대는 살구색(`theme.directionColors`). 위에 이름 + 필드 알약이 따라다닌다(`SYN` / `seq = x, SYN=1`). 연결선을 1초에 건넌다.
- **실패**: 손실·보내지 않음은 빨간 원이 터지듯 번진 뒤 작은 ✕ 표시가 남는다(`FailMark`). 과거 패킷은 점선 + 시계 아이콘, 모르는 요청은 ? 아이콘.
- **무대에는 꼭 필요한 글만**: 기기 이름, 상태 이름, 패킷 이름과 필드, 왼쪽 위 설명 칩(`SequenceState.notes`, `after` 메시지가 도착하면 미끄러져 등장), 왼쪽 아래 범례(패킷 색의 뜻). 메시지 기록과 뜻풀이는 오른쪽 설명의 "주고받은 메시지".
- **배치 방향은 왼쪽 아래 → 오른쪽 위**(월드 -y, 레인 좌표 `t` → `(0, -t)`). 먼 오브젝트부터 그린다.
- **카메라**(`camera.ts`): 기본 배율 `VIEW_W` 공통, 확대하지 않고 오브젝트가 많으면 `MAX_ZOOM_OUT`까지 축소, 넘치면 지금 주고받는 쪽으로 이동. 왼쪽 위 설명·범례 자리는 비워 둔다.
- 장면에 처음 들어오면 블록이 살짝 위에서 내려앉고, 그 뒤에 상태 알약과 메시지가 시작된다. Phase가 바뀌어도 장면은 이어지고 이번 Phase의 메시지만 재생한다. **앞으로 올 단계는 미리 보여 주지 않는다.**
- **설명 읽을 시간**: 설명 칩이 붙은 메시지가 도착하면 칩이 나타난 뒤 `READ_MS`(2.2초) 동안 기다렸다가 다음 메시지를 보낸다 (`timeline.ts`). 마지막 설명도 이만큼 읽은 뒤에 자동재생이 넘어간다.
- **topology 엔진**(`src/scenes/topology/`, 6-1부터): 레인 위 노드(블록 + 아이콘 + 이름), 연결선(위험 경로는 빨간 점선), 여러 노드를 거쳐 가는 패킷(블록에서 나올 때 0.18초 동안 선명해지고 들어갈 때 0.18초 동안 흐려진다. 출발·중간·끝 블록 모두 같은 규칙, `FADE_MS`), 노드에 붙는 알약(공격 빨강·용어 연보라·빠진 장치 호박·정보 종이색은 블록 위에 쌓고, 방어 연두는 블록 오른쪽 아래에 쌓음), 바닥 점선 구역(레인 위 이웃한 노드 여러 개를 감쌀 수 있음). 재생은 비트(flow · tags · zone) 순서이고 sequence와 같은 규칙(미리 보여 주지 않음, 설명 칩 뒤 읽을 시간, 다시 보기)을 따른다. Phase가 바뀌어도 같은 노드는 그대로, 새 노드만 내려앉는다.
- 블록 아이콘(`iso/glyphs.tsx`): monitor · server · browser · wifi · globe · shield · db · spy · door · idcard · card · elevator · clipboard · person. 아무 아이콘이나 얹는 블록은 `IsoNode`.
- 자동재생은 장면이 끝난 뒤 다음 Phase로 넘어간다(`scenes/duration.ts`). Phase 사이 1.5초 쉼.
- 진행 바의 ↻(**이 단계 다시 보기**)는 Phase를 그대로 두고 지금 Phase의 애니메이션만 처음부터 다시 재생한다 (`replayCount` → 장면의 `replay`).

## 7. 개발 순서 (마일스톤)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **M0** 셸 | 3단 레이아웃 + 하단 진행 바 + 라우팅 + 더미 데이터 | URL로 Week/Step/Phase 이동, 키보드 조작 동작 |
| **M1** 수직 슬라이스 | `sequence` 엔진 + **3-4 3-Way Handshake** 1개 완성 | 사이드바 → 무대 → 하단 바 → 오른쪽 패널이 모두 연동되고, 직접 해보기에서 SYN 손실 가능 |
| **M2** W3 완성 | `chart`, `anatomy`, `flow`, `compare`, `diagnose` 엔진 추가 | W3 전 Step 동작. 이 시점에 엔진 API 확정 |
| **M3** W2 | `topology`, `bits` 엔진 + W2 전 Step | 서브넷 계산기 정확도 검증(단위 테스트) |
| **M4** W4·W5 | 대부분 기존 엔진 재사용 + `sandbox`(CORS 빌더, Origin 비교기) | |
| **M5** W6·W7 | `sandbox`(공격 실습실, Wildcard 매칭) | |
| **M6** 마무리 | Quick Check, 오답 노트, Vercel 배포 | |

시험이 가깝다면 M1 이후에는 **시험 중요도가 높은 Step부터** 채운다 (CURRICULUM.md의 ★ 표시).
레슨을 다 만들지 못해도 각 Week의 ★ Step만 있으면 공부 도구로 바로 쓸 수 있다.

## 8. Claude Code에 일을 시키는 방법

1. 프로젝트 루트에 `CLAUDE.md`, `docs/`를 두고 `docs/lectures/`에 PDF 6개를 복사한다.
2. **한 번에 한 마일스톤씩** 요청한다. 예시 프롬프트:

```
M0을 진행해줘. docs/DESIGN.md의 2절 레이아웃과 3절 데이터 모델을 따르고,
content/w3에 Phase 3개짜리 더미 Step 2개만 넣어서 셸이 동작하는지 확인할 수 있게 해줘.
끝나면 실행 방법과 확인할 항목을 알려줘.
```

```
M1을 진행해줘. scenes/sequence 엔진을 만들고 CURRICULUM.md의 3-4 Step을 구현해.
오른쪽 패널 내용은 docs/lectures의 Week03 PDF p.10–11을 읽고 작성하되,
강의자료에 없는 내용은 넣지 말고 각 Phase에 출처 페이지를 달아줘.
```

```
CURRICULUM.md의 3-9 Step 데이터를 작성해줘. 먼저 Phase 목록과 각 Phase의
오른쪽 패널 초안을 보여주고, 내가 확인한 다음에 코드로 옮겨줘.
```

3. Step 데이터를 쓰기 전에 **Phase 목록을 먼저 텍스트로 확인**하는 습관을 들인다. 애니메이션 수정보다 텍스트 수정이 훨씬 싸다.
4. 계산이 들어가는 부분(서브넷, Seq/ACK 번호, BDP, Polling 비용)은 `lib/`에 순수 함수로 두고 **단위 테스트**를 같이 요청한다. 틀린 숫자로 공부하면 안 되니까.
